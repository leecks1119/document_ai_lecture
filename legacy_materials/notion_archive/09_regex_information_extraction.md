# 기존 교재 9. 정규식 기반 핵심 정보 추출

- 원본: [정규식 기반 핵심 정보 추출](https://app.notion.com/p/282707c7ae75811c907ddb994e3cd743)
- Notion 조회 시점의 최종 수정일: 2025-10-04

## 학습 목표

- NER 개념 이해
- 정규표현식으로 날짜·금액·연락처 추출
- LLM 기반 추출
- 정규식과 LLM의 하이브리드 처리

## 포함된 개념

- 범용 엔티티: 인명, 조직, 날짜, 금액, 위치
- 도메인 엔티티: 계약 금액·기간, 영수증 결제 정보, 의료 정보, 법 조항
- OCR 텍스트 → 정규화 → 규칙·NER·LLM → 후처리·검증 → JSON 흐름

## 코드 자산

### 기본 정규식

- 한국 전화번호
- 이메일
- 날짜
- 금액
- 계좌·카드 번호
- 주민등록번호 마스킹

### 영수증 추출

- `ReceiptInfo` dataclass
- `ReceiptExtractor`
- 키워드 근처의 금액 탐색
- 품목명·단가·수량·합계 파싱
- JSON 직렬화

### LLM 추출

- OCR 텍스트, 추출 필드, 규칙을 포함한 프롬프트
- 원문에 없는 값은 `null`
- 날짜와 금액 정규화
- JSON 파싱 실패 처리

### 하이브리드 추출

- 정규식 우선 처리
- 필수 필드 채움 비율로 단순 신뢰도 계산
- 누락 필드를 LLM 결과로 보완

## 문제점

- `openai.ChatCompletion.create`와 `gpt-4` 예제는 최신 SDK 방식이 아님
- 코드에 API 키 인자를 직접 전달하는 방식은 새 과정의 보안 원칙과 맞지 않음
- 주민등록번호 원문을 추출 목록으로 반환하는 예제는 교육용으로 부적절
- 조직명과 금액 정규식은 오탐 가능성이 높음
- `except:`와 같은 광범위 예외 처리가 포함됨
- “수작업 검토 80% 단축”은 근거가 없음

## 개편 판단

- 영수증 스키마와 “없는 값은 null” 규칙은 4교시 핵심 자료로 재사용
- 정규식은 7교시 날짜·금액·이메일·전화번호 검증에 활용
- 4교시의 추출은 생성형 AI 프롬프트와 mock JSON 중심으로 단순화
- 실제 API 호출은 선택 실습으로 분리하고 `.env`를 사용
- 주민등록번호 예제는 제거하고 개인정보 최소 수집 원칙을 설명

판정: **높은 재사용 가치가 있으나 코드와 개인정보 예시는 전면 수정**
