## 2. P1 — 구현 전 필수 수정

### P1-1. 교육 환경 기준 통일

`docs/curriculum.md`의 로컬·Python 3.12.9·PaddleOCR·Streamlit 대체 표현을 Colab 기본, Python 3.12.x, EasyOCR 선택, Gradio 기본으로 통일한다.

완료 기준: 커리큘럼과 청사진의 환경·필수 범위가 일치한다.

### P1-2. 2교시 실습과 산출물 정렬

바운딩 박스 시각화 함수는 완성 코드로 제공하고 학습자는 결과 확인과 OCR 텍스트 저장만 수행한다. EasyOCR 설치와 모델 다운로드는 선택 셀로 이동한다.

완료 기준: 필수 실습의 유일한 산출물은 `ocr_text.txt`다.

### P1-3. 3교시 원문 보존과 fallback

fallback 입력은 `SAMPLE_OCR_TEXT`로 통일한다. 결과에는 `raw_text`, `cleaned_lines`, `change_log`를 함께 보존한다.

완료 기준: mock에서도 학습자가 정제 과정을 수행하며 원문과 변경 내역이 남는다.

### P1-4. 6교시 명시적 mock 전환

업로드 또는 OCR 실패 후 관련 없는 샘플 결과를 자동 표시하지 않는다. 오류를 먼저 표시하고 학습자가 `샘플로 계속`을 선택해야 한다. 화면에 `MOCK 결과`를 항상 표시한다.

완료 기준: 실제 결과와 mock 결과를 혼동할 수 없다.

### P1-5. 7교시 범위 축소

테스트 데이터와 CSV 보조 함수는 제공한다. 학습자는 필수값과 품목 합계 규칙 두 가지만 완성한다. 이메일·전화번호 검증은 삭제한다.

완료 기준: 이전 앱 없이 제공 JSON만으로 실습 가능하고 직접 코딩은 10~15분 분량이다.

### P1-6. 8교시 산출물 하나로 제한

정상·누락·mock 점검은 제공된 `run_smoke_test()` 한 번으로 자동화한다. 학습자의 유일한 제작물은 `business_application_card.md`다.

완료 기준: 8교시에는 새 앱 기능을 구현하지 않는다.

## 3. 교시별 시간·난이도 조정

| 교시 | 위험 | 조정 |
| --- | --- | --- |
| 1 | `FIELD_SPEC` 처음부터 코딩 | 빈 템플릿 제공 |
| 2 | 좌표 시각화와 OCR 동시 수행 | 시각화 함수 제공, OCR 선택화 |
| 3 | 정규화와 구조 분류 동시 구현 | 정규화 함수 일부 제공 |
| 4 | JSON·스키마·`null`·프롬프트 | 스키마 골격 제공, 일부 필드만 채우기 |
| 5 | 다섯 컴포넌트와 이벤트 | 화면 골격 제공, 버튼 연결만 완성 |
| 6 | 파일 검사·상태·mock·통합 | 보조 함수 제공, `process_document()`만 연결 |
| 7 | 세 테스트 사례와 CSV | 테스트 데이터와 CSV helper 제공 |

각 교시의 실습 시간은 약 23분이지만 직접 코딩은 10~15분을 넘지 않게 한다. 남은 시간은 실행, 결과 읽기, 오류 복구에 사용한다.

## 4. 누적 범위 제한

- 모든 노트북에 필요한 이전 산출물의 완성본을 포함해 독립 실행되게 한다.
- 실제 EasyOCR, 생성형 AI API, PDF 변환 내부 구현은 선택 섹션으로 이동한다.

- 8교시에는 새로운 코드를 가르치지 않는다.
- mock 처리 코드는 공통 helper를 재사용한다.

## 5. 이미지와 Notion 기준

- 교시당 도식 2개를 유지한다.
- 모든 이미지에 교육 목적과 대체 텍스트를 작성한다.
- 코드 스크린샷은 사용하지 않는다.
- 실제 OCR·API 선택 내용은 Notion에서 토글로 분리할 수 있게 표시한다.
- 각 교시는 `핵심 개념 → 비유 → 실습 → 기대 결과 → 문제 해결 → 형성평가` 순서를 유지한다.
- 공식 출처는 교시당 핵심 2~3개만 하단에 배치한다.
