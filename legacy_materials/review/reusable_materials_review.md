# 과거 자료 재사용 검토

검토 기준일: 2026-07-27

## 전체 결론

기존 자료는 OCR 기술을 깊게 체험하는 데는 풍부하지만, 새 과정의 목표인 `문서 업로드 → OCR → JSON 구조화 → 검증 → CSV → Gradio 앱`과 비교하면 설치·알고리즘·벤치마크 비중이 지나치게 크다.

가장 가치가 높은 자산은 다음과 같다.

1. 비정형 문서를 구조화 데이터로 바꾸는 Document AI 정의
2. OCR이 전체 파이프라인의 한 단계라는 흐름도
3. 깨끗한 이미지와 저품질 이미지의 OCR 결과 비교
4. 텍스트, 신뢰도, 바운딩 박스로 구성된 OCR 결과 구조
5. 키-값, 표, 반복 항목을 구분하는 문서 구조 설명
6. 영수증 JSON 스키마와 “없는 값은 null” 규칙
7. AI 코딩 도구를 이용한 요구사항→구현→검토→수정 반복
8. 검증, 오류 경로, 최종 체크리스트와 업무 적용 아이디어

| 3. PaddleOCR | 수정 후 재사용 | 텍스트·신뢰도·좌표 결과 구조 | 설치/API 재검증, 실회사 샘플 |

| 2026 리뉴얼안 | 기준 자료 | 8교시 순서와 산출물 | Streamlit을 Gradio로 갱신 |

## 바로 재사용할 수 있는 소재

### 1교시

- 비정형 문서와 구조화 데이터 비교
- 문서 자동화 처리 단계
- 표 구조 인식과 웹 도구에 대한 교육생 관심
- OCR 도입 고려사항
- 영수증·신청서·견적서·점검표 사례

### 2교시

- OCR 결과의 텍스트, 신뢰도, 위치 정보
- 정상 이미지와 노이즈 이미지 비교
- Ground Truth와 인식 오류 찾기
- 저신뢰도 단어 표시

### 3교시

- 키-값과 표의 차이
- 셀 좌표에서 행·열 구조를 만드는 개념
- 기울기, 노이즈, 병합 셀 등 대표 실패 사례

### 4교시

- 영수증 추출 필드
- 원문에 없는 값은 `null`
- 금액과 날짜 정규화
- 정규식, 전문 모델, LLM의 역할 비교

### 5~6교시

- 요구사항을 작은 기능으로 분리하는 AI 코딩 흐름
- 파일 업로드, JSON, 표 출력을 요청하는 Gradio 프롬프트
- OCR·추출·UI 모듈 분리

### 7교시

- 신뢰도와 업무 위험도에 따른 검토 분기
- 필수 필드와 형식 검증
- DataFrame과 CSV 변환

### 8교시

- 정상·실패·mock 경로 체크리스트
- 개인정보와 외부 서비스 전송 검토
- 10개 업무 활용 아이디어
- OCR 품질·속도·비용·배포 방식 선택 기준

## 새로 제작해야 하는 자료

- 2026년 공식 근거를 사용한 OCR와 Document AI 비교
- Codex 설치와 저장소 협업 방법
- Gradio 기반 앱 화면
- 생성형 AI 프롬프트와 JSON 스키마의 초급자 설명
- OCR와 API 실패 시 mock 모드 안내
- 날짜·금액·이메일·전화번호 검증 예제
- CSV 다운로드까지 연결된 완성 앱
- 실제 개인정보가 없는 영수증·신청서·견적서 샘플

## 제외할 범위

- 세 OCR 엔진 동시 설치
- OCR 앙상블 구현
- 고급 Hough·Sauvola·병합 셀 알고리즘 구현
- 모델 파인튜닝
- Kafka, Airflow, ELK, Prometheus와 같은 운영 아키텍처
- 데이터베이스, Docker, 배포 자동화
- 특정 제품이나 기업의 근거 없는 순위

## 권장 활용 순서

1. 과거 자료에서 개념·비유·실습 아이디어만 선택한다.
2. `fact_check_backlog.md`의 항목을 먼저 해결한다.
3. 새 코드 구조와 mock 모드에 맞춰 예제를 다시 구현한다.
4. `curriculum_mapping.md`를 기준으로 교시별 교재에 배치한다.
5. 실행 검증을 통과한 내용만 Notion 새 교재에 등록한다.
