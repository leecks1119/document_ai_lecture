# 1교시. 한국 영수증으로 구분하는 OCR·VLM·Document AI

문서 자동화라는 말을 들으면 가장 먼저 “영수증 사진을 AI에게 보여 주면 Excel이 만들어지는 것”을 떠올리기 쉽습니다. 실제 업무에서는 그 사이에 여러 단계가 필요합니다. 글자를 읽어야 하고, 필요한 항목을 찾아야 하며, 계산이 맞는지 확인하고, 잘못된 값은 사람이 고쳐야 합니다.

이번 시간에는 영수증 한 장을 따라가며 각 기술이 어느 일을 맡는지 살펴봅니다.

## 먼저 영수증을 살펴봅시다

![개인정보와 거래 식별 영역을 가린 2025년 한국 음식점 영수증](../sample_docs/public_receipts/korea/taebaek_restaurant_2025_redacted.png)

위 영수증에서 `합계 금액 76,000`을 찾아보세요. 사람이 이 값을 Excel에 옮길 때는 다음 사실을 자연스럽게 판단합니다.

- `76,000`은 상품 가격 하나가 아니라 전체 결제 금액입니다.
- 쉼표는 금액을 읽기 쉽게 표시한 기호이므로 데이터에는 정수 `76000`으로 저장할 수 있습니다.
- 품목 금액을 더한 값과 합계가 같은지 확인할 수 있습니다.
- 원본을 보지 않고 숫자만 받으면 이 값이 어디에서 왔는지 알기 어렵습니다.

컴퓨터가 같은 일을 하려면 이러한 판단을 여러 기술과 규칙으로 나누어 구현해야 합니다.

## OCR, 멀티모달 AI, VLM은 무엇이 다를까요?

### OCR은 글자와 위치를 읽습니다

OCR(Optical Character Recognition)은 이미지 속 글자를 컴퓨터가 다룰 수 있는 텍스트로 바꾸는 기술입니다. 최근 OCR 제품은 문자열뿐 아니라 글자가 있던 위치와 모델의 신뢰도도 함께 제공합니다.

예를 들어 OCR은 다음과 같은 결과를 만들 수 있습니다.

```text
텍스트: 합계 금액 76,000
위치: 영수증 아래쪽 사각형 영역
신뢰도: 0.96
```

여기서 `0.96`은 모델이 이 글자를 비교적 확신한다는 신호입니다. 결제 금액이 실제로 맞다는 업무적 보증은 아닙니다.

### 멀티모달 AI는 여러 형태의 정보를 함께 다룹니다

멀티모달 AI는 이미지, 텍스트, 음성처럼 서로 다른 형태의 정보를 함께 처리하는 AI를 가리키는 넓은 표현입니다. 문서 사진과 질문을 함께 입력해 답을 얻는 작업도 멀티모달 활용에 포함됩니다.

### VLM은 이미지와 언어를 함께 이해하는 모델입니다

VLM(Vision-Language Model)은 멀티모달 AI 가운데 이미지와 언어를 함께 처리하는 모델입니다. 문서의 제목, 표, 주변 문장을 참고해 `76,000`이 합계일 가능성을 판단하고 다음과 같은 구조 초안을 만들 수 있습니다.

```json
{
  "total_amount": 76000
}
```

VLM은 문맥을 이용할 수 있다는 장점이 있지만, 원본에 없는 값을 그럴듯하게 만들 가능성도 있습니다. 따라서 결과의 모양이 자연스럽다고 해서 바로 정답으로 사용해서는 안 됩니다.

### Document AI는 문서를 업무 데이터로 바꾸는 기술과 과정입니다

Document AI는 하나의 모델 이름이 아닙니다. 문서 분류, OCR, 레이아웃 분석, 항목 추출, 값 정리, 규칙 검증처럼 문서를 데이터로 바꾸는 데 필요한 기술과 처리 과정을 함께 가리킵니다.

문서의 종류와 난이도에 따라 OCR만 사용할 수도 있고, VLM을 사용할 수도 있으며, 두 방법을 조합할 수도 있습니다. 항상 `OCR 다음에 VLM`을 실행해야 하는 것은 아닙니다.

### IDP는 실제 회사 업무에서 운영하는 범위까지 포함합니다

IDP(Intelligent Document Processing)는 Document AI의 처리 능력을 회사의 업무 절차와 연결한 개념입니다. 어떤 문서를 받을지, 오류는 누가 검토할지, 승인된 결과를 ERP나 Excel에 어떻게 전달할지, 처리 기록을 얼마나 보관할지까지 다룹니다.

![Multimodal AI, VLM, OCR, Document AI 역량과 IDP 운영 범위의 관계](assets/01/01_terms_relationship.svg)

한 문장으로 비유하면 다음과 같습니다.

> OCR은 영수증을 받아 적는 사람이고, VLM은 문맥을 보고 표 초안을 만드는 사람입니다. Document AI는 두 사람의 도구와 검증 규칙을 묶은 작업 방식이며, IDP는 이 작업을 회사에서 안전하게 운영하는 업무 절차입니다.

## 문서 한 장이 업무 데이터가 되는 과정

기업마다 실제 구현 방법은 다르지만, 전체 흐름은 다음 다섯 구간으로 이해할 수 있습니다.

| 구간 | 해야 할 일 | 영수증 예 |
| --- | --- | --- |
| 문제 정의 | 줄이고 싶은 업무와 성공 기준을 정합니다. | 수기 입력 시간을 줄이고 금액 오류를 찾습니다. |
| 입력 준비 | 문서 형식, 보안, 이미지 품질을 확인합니다. | 승인된 영수증 한 장의 흐림과 기울기를 확인합니다. |
| 읽기와 구조화 | OCR 또는 VLM으로 내용을 읽고 필요한 항목을 정리합니다. | 상호명, 날짜, 품목, 합계를 JSON으로 만듭니다. |
| 검증과 사람 확인 | 계산, 자료형, 원본 근거를 검사하고 사람이 수정·승인합니다. | 품목 합계가 76,000원인지 원본과 비교합니다. |
| 저장과 개선 | 승인된 결과를 업무 시스템에 저장하고 오류 원인을 기록합니다. | Excel로 내려받고 자주 틀리는 항목을 기록합니다. |

세부 절차로 나누면 업무 목표와 성공 기준 설정, 입력 접수, 품질 확인, 문서 분류, 글자 판독, 구조 복원, 항목 추출, 값 정규화, 규칙 검증, 예외 처리, 사람 승인, 결과 저장, 운영 개선이 이어집니다. 보안과 개인정보 보호는 마지막 단계가 아니라 이 모든 과정을 가로지르는 조건입니다.

## 직접 해보기: 76,000원의 이동 경로 찾기

Colab을 열고 영수증의 합계가 처리 과정마다 어떤 모습으로 바뀌는지 연결해 봅니다.

1. OCR 단계에서는 원문 문자열인 `합계 금액 76,000`을 찾습니다.
2. 구조화 단계에서는 이 문자열을 `total_amount` 항목의 후보로 정합니다.
3. 정규화 단계에서는 쉼표를 제거하고 정수 `76000`으로 바꿉니다.
4. 검증 단계에서는 품목 합계와 비교하고 원문 근거가 남아 있는지 확인합니다.
5. 사람이 원본을 확인한 뒤에만 Excel로 전달합니다.

![영수증 원문에서 근거·정규화·검증·사람 확인을 거쳐 Excel로 가는 흐름](assets/01/03_receipt_evidence_flow.svg)

노트북에는 각 단계가 만드는 결과 파일을 연결하는 짧은 빈칸이 있습니다. 먼저 자신의 생각대로 적어 본 뒤 힌트와 완성 예시를 비교하세요. 중요한 것은 파일명을 외우는 일이 아니라, 앞 단계의 결과가 다음 단계에서 어떻게 사용되는지 설명하는 것입니다.

실습을 마치면 `course_outputs/receipt_pipeline_trace.json` 파일이 만들어집니다. 파일을 열어 `76000` 옆에 원본 문자열인 `합계 금액 76,000`이 함께 저장되어 있는지 확인합니다.

## 이번 시간의 정리

- OCR은 문서 이미지에서 글자와 위치를 읽습니다.
- VLM은 이미지와 언어를 함께 보고 문맥을 반영한 구조 초안을 만들 수 있습니다.
- Document AI는 문서를 업무 데이터로 바꾸기 위한 여러 기술과 검증 과정을 포함합니다.
- 실제 업무에서는 오류 처리, 사람 승인, 시스템 연결까지 설계해야 합니다.
- AI가 읽은 값에는 원본에서 찾을 수 있는 근거가 남아 있어야 합니다.

다음 질문에 자신의 말로 답해 보세요.

1. OCR 신뢰도가 높아도 합계 금액을 원본과 비교해야 하는 이유는 무엇인가요?
2. VLM이 만든 JSON의 모양이 올바르더라도 내용이 틀릴 수 있는 이유는 무엇인가요?
3. 회사에서 Document AI를 사용하려면 모델 외에 어떤 절차가 필요할까요?

다음 교시에는 같은 영수증에 PaddleOCR을 직접 실행하고, 글자·위치·신뢰도가 실제로 어떻게 나오는지 확인합니다.
