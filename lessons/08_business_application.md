## 4. 핵심 개념

### 4.1 자동화 후보는 처리량만으로 고르지 않는다

- 반복해서 처리하는 문서인가?
- 잘못 추출되면 어떤 문제가 생기는가?
- 사람 판단이 필요한 예외가 자주 생기는가?

반복량이 많아도 오류 영향이 매우 크거나 예외가 많다면 전면 자동화보다 보조 도구가 적합할 수 있다.

### 4.2 데이터가 어디로 가는지 확인한다

Colab 파일은 영구 저장소가 아니며 Gradio 공유 주소는 공개될 수 있다. 실제 업무 적용 전에는 다음을 확인한다.

- 필요한 개인정보만 처리하는가?
- 외부 API 전송이 조직에서 허용되는가?
- 누가 결과에 접근하는가?
- 원본과 결과를 언제 삭제하는가?

### 4.3 사람의 승인까지가 업무 흐름이다

> **쉬운 비유**
> Document AI 앱은 신입 사원이고 사람 검토자는 최종 결재자다.

비유의 한계: 모든 값을 사람이 다시 입력하게 만들면 자동화 의미가 없다. 오류 영향이 큰 필드와 예외에 검토를 집중한다.

## 5. 전체 실습 흐름

```text
run_smoke_test() 한 번 실행
  → 정상·누락·mock 경로 확인
  → 적용할 문서 하나 선택
  → 여섯 칸 카드 작성
  → 동료와 검토 책임 확인
```

## 6. 단계별 실습

### 실습 1. 한 장짜리 적용 카드 작성하기

먼저 제공된 점검 함수를 한 번 실행한다.

```python
results = run_smoke_test()
assert all(results.values())
results
```

이 함수는 새 코드를 가르치기 위한 것이 아니라 이전 단계가 연결됐는지 확인하기 위한 완성 코드다.

그다음 학습자의 유일한 제작물인 적용 카드를 작성한다.

| 항목 | 예시 |
| --- | --- |
| 입력 문서 | 사내 비용 처리용 영수증 |
| 필요한 필드 | 상호명, 날짜, 품목, 총액 |
| 오류 영향 | 총액 오류 시 정산 금액이 달라짐 |
| 사람 검토자 | 비용 처리 담당자 |
| 저장 형식과 위치 | 승인 후 CSV, 승인된 저장소 |
| 삭제 시점 | 조직의 보존 기준에 따름 |

**기대 결과**

- `run_smoke_test()` 네 항목이 모두 `True`다.
- `business_application_card.md`의 여섯 칸이 작성된다.

**mock 대체 경로**

앱이나 노트북 실행이 어려우면 제공된 정상·누락·mock 결과 설명을 읽고 카드에서 문제 지점과 검토자를 표시한다.

## 7. Codex 활용

### 요청 목표

업무 적용 카드에서 책임과 데이터 처리 기준이 빠지지 않았는지 확인한다.

### 실습 프롬프트

```text
목표: Document AI 업무 적용 카드의 누락 항목을 검토해줘.
맥락: 합성 영수증 실습을 실제 비용 처리 업무에 적용하려고 해.
제약조건: 법률 자문이나 대규모 시스템 설계를 하지 마.
완료 기준: 입력, 필드, 오류 영향, 검토자, 저장, 삭제 여섯 항목만 점검해줘.
```

### 생성 결과 확인

- 최종 승인자가 지정돼 있는가?
- 실제 개인정보의 외부 전송 여부를 확인했는가?
- 저장과 삭제 기준이 모두 있는가?

## 8. 문제 해결

| 증상 | 원인 | 해결 방법 |
| --- | --- | --- |
| 점검 결과 일부가 `False` | 이전 단계 오류 | 해당 항목 이름으로 6~7교시 함수 확인 |
| 적용 범위가 너무 큼 | 여러 문서·부서를 한 번에 선택 | 문서 한 종류와 업무 한 단계로 축소 |
| 검토자가 불명확함 | 책임자 미정 | 실제 적용 전 업무 소유자와 승인자 지정 |
