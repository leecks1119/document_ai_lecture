# 4교시. 멀티모달·생성형 AI 기반 핵심 정보 추출

지금까지는 OCR로 글자를 읽고 위치를 이용해 순서를 정리했습니다. 이제 사람이 실제로 사용할 항목인 상호명, 날짜, 품목, 합계를 JSON으로 만들어야 합니다.

이 작업에는 여러 방법이 있습니다. 이번 시간에는 **OCR 결과에 규칙을 적용하는 방법**과 **문서 이미지를 VLM에 직접 보여 주는 방법**을 비교합니다. 어느 방법을 선택하든 원본 근거와 검증이 필요하다는 점도 함께 확인합니다.

> **이번 시간의 도착점:** OCR+규칙 결과와 VLM 구조 초안의 차이를 구분하고, 각 값의 원본 근거와 실행 출처를 확인합니다.

## 두 가지 추출 방법을 비교해 봅시다

### 방법 1. OCR 결과에 규칙을 적용합니다

```text
문서 이미지
  → OCR로 글자와 위치 판독
  → 읽기 순서와 품목 행 복원
  → 정규식과 Python 규칙으로 필요한 값 찾기
  → JSON
```

예를 들어 `합계 금액 76,000`이라는 줄을 찾고, 쉼표를 제거해 정수 `76000`으로 바꾸는 규칙을 작성할 수 있습니다.

이 방법은 문서 형식이 일정할 때 빠르고 저렴하며, 어떤 규칙으로 값을 찾았는지 설명하기 쉽습니다. 반면 상호명의 위치나 합계 표현이 자주 바뀌면 규칙도 계속 수정해야 합니다.

### 방법 2. 문서 이미지를 VLM에 보여 줍니다

```text
문서 이미지 + 추출할 항목과 형식을 설명한 지시문
  → VLM이 글자·배치·문맥을 함께 살펴봄
  → 구조화된 결과 초안
  → JSON
```

VLM에는 “상호명, 날짜, 품목, 합계를 다음 JSON 형식으로 작성하라”는 지시문을 함께 전달할 수 있습니다. 모델은 표의 배치와 주변 문맥을 이용해 값을 찾습니다.

VLM이 언제나 별도의 OCR 결과를 먼저 받아야 하는 것은 아닙니다. 문서 VLM 가운데에는 이미지에서 글자와 구조를 함께 처리하는 모델도 있습니다. 다만 모델 내부에서 어떤 방식으로 처리하든, 최종 결과를 원본과 검증해야 한다는 원칙은 같습니다.

수업의 비교 예제는 PaddleOCR-VL 계열처럼 문서 이미지와 구조를 함께 처리하는 경로를 참고합니다. 특정 모델의 사용법을 외우기보다, 모델이 만든 구조 초안을 원본 근거와 함께 검토하는 방법에 집중합니다.

![영수증이 문서 VLM의 구조 초안을 거쳐 업무 JSON이 되는 흐름](assets/04/01_receipt_to_json.svg)

## JSON 모양이 맞는 것과 내용이 맞는 것은 다릅니다

다음 결과는 형식만 보면 정상적인 JSON입니다.

```json
{
  "merchant": "이태리집",
  "transaction_date": "2025-10-04",
  "total_amount": 76000
}
```

하지만 업무에서 사용하기 전에는 다음 세 가지를 확인해야 합니다.

1. **형식:** 필요한 항목이 있고 날짜와 금액의 자료형이 맞는가?
2. **원본 근거:** 각 값이 문서의 어느 글자에서 왔는가?
3. **불확실성:** 읽지 못한 값을 추측하지 않고 비워 두었는가?

![VLM 중간 결과, JSON 스키마, 원문 근거를 확인하는 그림](assets/04/02_three_checks.svg)

> VLM은 문서를 읽고 표 초안을 만드는 신입 사원과 비슷합니다. 보기 좋은 표를 만들었더라도 원본과 같은지는 담당자가 확인해야 합니다.

## 직접 해보기: OCR과 규칙으로 업무 JSON 만들기

### 1. 정리된 영수증을 불러옵니다

기본값 `USE_COURSE_EXAMPLE=True`는 새 Colab에서도 같은 공개 영수증의 검수된
정제 결과로 바로 실행됩니다. 3교시 결과를 이어서 처리하려면 값을 `False`로
바꾸고 `clean_receipt.json`을 선택합니다.

### 2. 상호명과 날짜를 찾습니다

정리된 줄에서 상호명과 `거래일시`가 있는 줄을 찾습니다. 날짜와 시간은 원문을 보존하면서 프로그램이 비교하기 쉬운 형식으로 나눕니다.

```text
원문: 거래일시 2025-10-04 12:33:37
정제한 날짜: 2025-10-04
```

### 3. 품목을 반복되는 데이터로 만듭니다

품목 한 줄을 `품목명`, `단가`, `수량`, `금액`으로 나눕니다. 다섯 개 품목이 JSON 배열의 다섯 항목으로 만들어지는지 확인합니다.

```json
{
  "name": "콜라",
  "unit_price": 2000,
  "quantity": 3,
  "amount": 6000
}
```

### 4. 합계와 원본 근거를 함께 저장합니다

금액은 계산에 사용할 정수와 원본에서 읽은 문자열을 함께 남깁니다.

```json
{
  "total_amount": 76000,
  "evidence": {
    "total_amount": {
      "raw_value": "합계 금액 76,000"
    }
  }
}
```

원본에서 값을 찾지 못했다면 `0`이나 비슷해 보이는 숫자를 넣지 않고 `null`로 둡니다. `0원`과 `읽지 못함`은 전혀 다른 의미입니다.

## VLM 결과와 나란히 비교하기

필수 실습은 비용 없이 실행할 수 있는 OCR과 규칙 경로로 진행합니다. 수업에서는 같은 공개 영수증을 문서 VLM으로 처리하는 과정도 한 번 시연으로 확인합니다. 수강생 노트북에는 시연 결과와 같은 구조의 검수된 비교 예제가 들어 있습니다.

두 결과를 열고 다음 항목을 비교해 보세요.

| 비교할 내용 | OCR과 규칙 | VLM |
| --- | --- | --- |
| 상호명과 합계를 찾는 방식 | 미리 작성한 위치·문자 규칙 | 이미지와 지시문의 문맥 |
| 문서 모양이 바뀌었을 때 | 규칙을 수정할 수 있음 | 다양한 배치에 대응할 가능성이 있음 |
| 결과를 설명하기 쉬운가 | 사용한 규칙을 확인할 수 있음 | 모델 판단 과정을 모두 알기 어려움 |
| 주요 부담 | 규칙 유지보수 | 비용, 지연, 보안, 재현성 |
| 공통으로 필요한 일 | 원본 근거 확인과 업무 규칙 검증 | 원본 근거 확인과 업무 규칙 검증 |

준비된 비교 예제는 현재 Colab에서 VLM을 새로 호출한 결과가 아닙니다. 실제 시연 결과와 교육용 비교 예제를 구분해서 살펴보세요.

## 어떤 방법을 선택해야 할까요?

양식이 일정하고 필요한 항목이 적다면 OCR과 규칙이 더 단순하고 저렴할 수 있습니다. 표가 복잡하거나 문서마다 배치가 크게 달라 규칙을 유지하기 어렵다면 VLM을 검토할 수 있습니다.

선택할 때는 정확도만 보지 않습니다. 처리 비용, 응답 시간, 개인정보 전송, 결과 재현성, 오류가 업무에 미치는 영향, 사람이 검토할 수 있는지도 함께 판단해야 합니다.

## 이번 시간의 정리

- OCR과 규칙은 읽은 글자를 명시적인 코드로 구조화합니다.
- VLM은 이미지와 지시문을 함께 보고 구조 초안을 만들 수 있습니다.
- 두 방법은 서로 다른 경로이며 언제나 순서대로 실행해야 하는 것은 아닙니다.
- JSON 형식이 올바른 것과 값이 정확한 것은 별개의 문제입니다.
- 중요한 값은 원본 근거와 함께 저장하고 검증해야 합니다.

다음 교시에는 지금까지 만든 처리 결과를 파일 업로드, 실행 버튼, 결과 화면이 있는 간단한 웹앱으로 보여 줍니다.
