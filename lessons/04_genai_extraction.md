# 4교시. 멀티모달·생성형 AI 기반 핵심 정보 추출

지금까지는 OCR로 글자를 읽고 위치를 이용해 순서를 정리했습니다. 이제 사람이 실제로 사용할 항목인 상호명, 날짜, 품목, 합계를 JSON으로 만들어야 합니다.

이 작업에는 여러 방법이 있습니다. 이번 시간에는 **OCR 결과에 규칙을 적용하는 방법**과 **문서 이미지를 실제 VLM으로 읽는 방법**을 직접 실행해 비교합니다. 어느 방법을 선택하든 원본 근거와 검증이 필요하다는 점도 함께 확인합니다.

> **이번 시간의 도착점:** 공개 영수증 한 장을 `PaddleOCR-VL-1.6`으로 직접 읽고, OCR+규칙 결과와 다른 점을 원본에서 설명합니다.

[4교시 Colab 실습 열기](https://colab.research.google.com/github/leecks1119/document_ai_lecture/blob/master/colab/04_genai_extraction.ipynb)

## 두 가지 추출 방법을 비교해 봅시다

### 방법 1. OCR 결과에 규칙을 적용합니다

```text
문서 이미지
  → OCR로 글자와 위치 판독
  → 읽기 순서와 품목 행 복원
  → 정규식과 Python 규칙으로 필요한 값 찾기
  → JSON
```

예를 들어 `합계 금액 76,000`이라는 줄을 찾고, 쉼표를 제거해 정수 `76000`으로 바꾸는 규칙을 작성할 수 있습니다.

이 방법은 문서 형식이 일정할 때 빠르고 저렴하며, 어떤 규칙으로 값을 찾았는지 설명하기 쉽습니다. 반면 상호명의 위치나 합계 표현이 자주 바뀌면 규칙도 계속 수정해야 합니다.

### 방법 2. 문서 이미지를 문서 VLM에 보여 줍니다

```text
문서 이미지 픽셀
  → 레이아웃 영역 탐지와 읽기 순서 결정
  → VLM이 각 영역의 글자·표·문맥을 함께 인식
  → Markdown과 구조 JSON
  → Python 규칙으로 업무 JSON 변환
```

이번 실습의 전체 파이프라인 이름은 `PaddleOCR-VL-1.6`이고, 그 안에서 이미지를 언어와 함께 처리하는 모델은 `PaddleOCR-VL-1.6-0.9B`입니다. 전체 파이프라인은 레이아웃 분석, 영역 자르기, 읽기 순서 처리, VLM 인식, 결과 조립을 차례로 수행합니다.

이 모델의 기본 결과는 자유로운 업무 JSON이 아니라 문서의 Markdown과 구조 JSON입니다. 따라서 상호명·날짜·품목·합계라는 우리 업무 스키마로 옮기는 Python 후처리를 별도로 실행합니다. `VLM이 문서를 읽은 단계`와 `규칙이 업무 필드로 옮긴 단계`를 구분해야 결과를 설명하고 고칠 수 있습니다.

VLM이 언제나 별도의 OCR 결과를 먼저 받아야 하는 것은 아닙니다. 문서 VLM 가운데에는 이미지에서 글자와 구조를 함께 처리하는 모델도 있습니다. 다만 최종 결과를 원본과 검증해야 한다는 원칙은 같습니다.

![영수증이 문서 VLM의 구조 초안을 거쳐 업무 JSON이 되는 흐름](assets/04/01_receipt_to_json.svg)

## JSON 모양이 맞는 것과 내용이 맞는 것은 다릅니다

다음 결과는 형식만 보면 정상적인 JSON입니다.

```json
{
  "merchant": "이태리집",
  "transaction_date": "2025-10-04",
  "total_amount": 76000
}
```

하지만 업무에서 사용하기 전에는 다음 세 가지를 확인해야 합니다.

1. **형식:** 필요한 항목이 있고 날짜와 금액의 자료형이 맞는가?
2. **원본 근거:** 각 값이 문서의 어느 글자에서 왔는가?
3. **불확실성:** 읽지 못한 값을 추측하지 않고 비워 두었는가?

![VLM 중간 결과, JSON 스키마, 원문 근거를 확인하는 그림](assets/04/02_three_checks.svg)

> VLM은 문서를 읽고 표 초안을 만드는 신입 사원과 비슷합니다. 보기 좋은 표를 만들었더라도 원본과 같은지는 담당자가 확인해야 합니다.

## 직접 해보기: 실제 VLM과 OCR+규칙 비교하기

### 1. 실제 모델에 넣을 이미지를 고릅니다

처음에는 `제공 예제`를 사용합니다. 다음 실행에서는 `내 컴퓨터에서 업로드`
또는 `인터넷 이미지 URL`로 이미지 한 장만 바꿉니다. 화면에 표시된 이미지와
`실제 VLM 입력 파일`이 내가 고른 자료와 같은지 먼저 확인합니다.

### 2. Colab GPU와 모델을 준비합니다

`런타임 → 런타임 유형 변경 → T4 GPU`를 선택합니다. GPU 확인 셀에는 GPU 이름,
전체 파이프라인 `PaddleOCR-VL-1.6`, 실제 VLM 모델
`PaddleOCR-VL-1.6-0.9B`, 추론 엔진 `transformers`가 표시됩니다.

오픈소스 모델을 로컬 추론하므로 API 키와 건당 호출 요금은 없습니다. 다만 무료
Colab GPU는 항상 배정된다고 보장되지 않으며, 처음 실행할 때 모델을 내려받아야
합니다. GPU가 없으면 모델 실행 셀은 명확한 오류를 내고 멈춥니다.

### 3. 현재 이미지를 실제 VLM으로 읽습니다

다음 한 줄이 핵심입니다.

```python
page_results = list(vlm_pipeline.predict(str(VLM_INPUT_PATH)))
```

`VLM_INPUT_PATH`에는 화면에서 확인한 현재 이미지가 들어 있습니다. 실행 뒤에는
반드시 `모델 실행 완료: True`와 실제 Markdown 앞부분을 확인합니다. 준비된
VLM 문자열로 바꾸는 코드는 없습니다.

### 4. VLM 결과를 업무 JSON으로 옮깁니다

모델이 복원한 Markdown에서 상호명, 날짜, 품목, 합계를 찾습니다. 금액은 계산에
쓸 정수와 원본에서 읽은 문자열을 함께 남깁니다.

```json
{
  "total_amount": 76000,
  "evidence": {
    "total_amount": {
      "raw_value": "합계 금액 76,000"
    }
  }
}
```

원본에서 값을 찾지 못했다면 `0`이나 비슷해 보이는 숫자를 넣지 않고 `null`로 둡니다. `0원`과 `읽지 못함`은 전혀 다른 의미입니다.

## 실제 실행 결과를 나란히 비교하기

두 결과를 열고 다음 항목을 비교해 보세요.

| 비교할 내용 | OCR과 규칙 | VLM |
| --- | --- | --- |
| 상호명과 합계를 찾는 방식 | OCR 원문에서 명시적 문자 규칙 | 이미지의 배치·글자·문맥을 복원한 뒤 업무 규칙 |
| 문서 모양이 바뀌었을 때 | 규칙을 수정할 수 있음 | 다양한 배치에 대응할 가능성이 있음 |
| 결과를 설명하기 쉬운가 | 사용한 규칙을 확인할 수 있음 | 모델 판단 과정을 모두 알기 어려움 |
| 주요 부담 | 규칙 유지보수 | GPU, 모델 다운로드, 지연, 보안, 재현성 |
| 공통으로 필요한 일 | 원본 근거 확인과 업무 규칙 검증 | 원본 근거 확인과 업무 규칙 검증 |

결과 JSON의 `provenance.model_executed`가 `true`인지 확인합니다. 값이 `false`라면
저장소의 빠른 코드 검사만 실행한 것이며 VLM 결과로 인정하지 않습니다.

## 실습 결과 확인하기

실습을 마치면 다음 파일이 만들어집니다.

- `receipt.json`: OCR과 규칙으로 만든 업무용 영수증 데이터
- `paddleocr_vl_raw.json`: 실제 모델의 구조 결과와 실행 기록
- `paddleocr_vl_result.md`: 실제 모델이 복원한 문서 Markdown
- `receipt_vlm.json`: VLM Markdown을 업무 스키마로 옮긴 결과
- `vlm_comparison.json`: OCR+규칙과 실제 VLM 결과의 필드별 비교

`receipt.json`은 7교시에서 검증하고 Excel로 저장할 때 다시 사용합니다.

## 어떤 방법을 선택해야 할까요?

양식이 일정하고 필요한 항목이 적다면 OCR과 규칙이 더 단순하고 저렴할 수 있습니다. 표가 복잡하거나 문서마다 배치가 크게 달라 규칙을 유지하기 어렵다면 VLM을 검토할 수 있습니다.

선택할 때는 정확도만 보지 않습니다. 처리 비용, 응답 시간, 개인정보 전송, 결과 재현성, 오류가 업무에 미치는 영향, 사람이 검토할 수 있는지도 함께 판단해야 합니다.

## 이번 시간의 정리

- OCR과 규칙은 읽은 글자를 명시적인 코드로 구조화합니다.
- 이번 실습은 `PaddleOCR-VL-1.6-0.9B`를 실제로 실행합니다.
- 문서 VLM은 이미지를 Markdown·구조 JSON으로 복원하고, Python 규칙은 이를 업무 JSON으로 옮깁니다.
- 두 방법은 서로 다른 경로이며 언제나 순서대로 실행해야 하는 것은 아닙니다.
- JSON 형식이 올바른 것과 값이 정확한 것은 별개의 문제입니다.
- 중요한 값은 원본 근거와 함께 저장하고 검증해야 합니다.

다음 교시에는 지금까지 만든 처리 결과를 파일 업로드, 실행 버튼, 결과 화면이 있는 간단한 웹앱으로 보여 줍니다.
