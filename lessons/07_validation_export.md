## 개념 10%: 정상·경고·오류와 승인은 별개입니다

| 결과 | 의미 | 다음 행동 |
| --- | --- | --- |
| `valid=true` | 차단 오류 없음 | 사람 원본 확인 |
| `warnings` | 자동 처리 가능하지만 확인 필요 | 검토 기록 남김 |
| `errors` | 업무 규칙 위반 | 수정 전 저장 금지 |

`valid=true`가 사람 승인을 뜻하지는 않습니다.

## 실습 90%

### 1. 다섯 종류의 규칙을 실행합니다

- 필수값: 상호명·날짜·총액·품목
- 자료형: 금액은 Boolean이 아닌 0 이상의 정수
- 품목 계산: `수량 × 단가 = 품목 금액`
- 합계 계산: `품목 합계 - 할인 + 세액 + 서비스 + 반올림 = 총액`
- 근거: 상호명·날짜·총액의 원본 근거

실제 영수증은 할인·세금·봉사료·반올림이 있을 수 있으므로 단순 품목 합계만 비교하지 않습니다.

오늘 영수증의 `부가세 6,906원`은 품목 가격 76,000원에 **이미 포함된 세액 내역**입니다. 따라서 `adjustments.tax`는 `0`이며 다시 더하지 않습니다.

```text
세액 표시 검증: 공급가액 69,094 + 포함 부가세 6,906 = 결제금액 76,000
지급액 검증: 품목 합 76,000 + 추가 조정 0 = 총액 76,000
```

### 2. 수식 주입을 막습니다

Excel 셀의 문자열이 공백이나 탭 뒤에 `=`, `+`, `-`, `@`로 시작해도 텍스트로 보호합니다.

```python
value.lstrip(" \t\r\n").startswith(("=", "+", "-", "@"))
```

### 3. 시나리오 A — 미승인 차단을 확인합니다

새 Colab 런타임이면 4교시에 내려받은 `receipt.json`을 먼저 업로드합니다. 파일이 없을 때만 `USE_PREPARED_INPUT=True`로 바꿉니다.

```text
DEFAULT_BLOCKED PASS: 미승인 Excel 없음
```

오류가 없더라도 `decision=PENDING`이면 `pending_review.xlsx`가 만들어지지 않아야 합니다.

### 4. 시나리오 B — 공개된 승인 정답을 실행합니다

원본에서 상호명·날짜·품목·총액을 직접 대조한 뒤, 노트북에 공개된 전체 정답 셀을 실행합니다.

```json
{
  "decision": "APPROVED",
  "reviewer": "learner",
  "reviewed_at": "2026-07-28T15:30:00+09:00",
  "note": "공개 비식별 원본과 대조 완료"
}
```

정상 결과:

```text
REVIEWED_APPROVED PASS: course_outputs/receipt_result.xlsx
CHECKPOINT 1/1 PASS: 미승인 차단 + 승인 후 Excel
```

### 5. Excel 세 시트를 확인합니다

![JSON이 검토 요약, 품목, 원문 근거 시트로 변환되는 그림](assets/07/02_json_to_excel.svg)

- `검토_요약`: 원문값·정제값·최종값·결정·검토자·시각·수정 이유
- `품목`: 품목 하나당 한 행
- `원문_근거`: 실행 모드·OCR 원문·필드 근거

실제 앱도 원본 대조 체크 전에는 다운로드 버튼을 숨기고, 승인 뒤에만 아래처럼 표시합니다.

![원본 대조 승인 뒤 검증된 Excel 다운로드가 열린 실제 앱 화면](assets/screens/app_approved_excel.png)

## 통과 기준

- 미승인 Excel은 존재하지 않습니다.
- 승인 기록이 Excel에 남습니다.
- 품목 합계와 총액이 검증됩니다.
- 공백·탭 뒤 수식 시작 문자도 보호됩니다.
- 세 시트가 생성됩니다.

## 막혔을 때

- 합계 오류면 품목 수량·단가·금액과 adjustments를 먼저 확인합니다.
- `receipt.json`이 없어도 준비 결과로 독립 실행할 수 있습니다.
- 파일이 열려 저장 오류가 나면 Excel을 닫고 다시 실행합니다.
- 오류가 있는데 승인값만 바꾸지 않습니다.
