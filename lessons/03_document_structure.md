# 3교시. 문서 구조 이해 및 추출 결과 정제

OCR은 글자를 읽지만, 그 글자가 같은 행에 있는지까지 완벽하게 알려 주지는
않습니다. 영수증의 품목명·단가·수량·금액도 각각 떨어진 글자로 나올 수 있습니다.

> **이번 시간의 도착점:** 영수증 한 장을 실제 `PP-OCRv5 Korean`으로 읽고,
> 글자 좌표를 이용해 품목 행 다섯 개를 다시 묶습니다.

[Colab 실습 열기](https://colab.research.google.com/github/leecks1119/document_ai_lecture/blob/master/colab/03_document_structure.ipynb)

![OCR 전후 정리 과정](assets/03/01_clean_before_after.svg)

## 오늘 확인할 한 가지

다음 네 글자는 OCR에서 별도 결과로 나올 수 있습니다.

```text
콜라    2,000    3    6,000
```

각 글자의 세로 위치가 비슷하면 같은 행으로 묶고, 가로 위치 순서로 정렬합니다.
이 과정을 거치면 단순한 글자 목록이 사람이 읽을 수 있는 품목 행이 됩니다.

## 직접 해보기

### 1. 이미지 한 장을 고릅니다

처음에는 제공 영수증을 사용합니다. 이후에는 `내 컴퓨터에서 업로드` 또는
`인터넷 이미지 URL`을 선택해 비식별 이미지 한 장으로 다시 실행할 수 있습니다.

화면의 원본 이미지와 `실제 모델 입력` 파일명이 같은지 확인합니다.

### 2. 실제 PP-OCRv5를 실행합니다

Colab에서 다음 함수가 현재 이미지를 직접 읽습니다.

```python
tokens = extract_with_paddleocr(INPUT_PATH)
```

실제 Colab 실행에서는 반드시 다음 문구를 확인합니다.

```text
실제 모델 실행: True
```

저장소 자동검사에서는 모델 다운로드만 생략하므로 `False`가 표시됩니다. 이 결과를
실제 모델 실행이라고 부르지 않습니다.

### 3. 글자를 행으로 다시 묶습니다

```python
layout_lines = reconstruct_spatial_lines(tokens)
```

출력에서 날짜, 품목, 합계가 각각 한 줄로 보이는지 확인합니다. 제공 영수증에서는
다음과 비슷한 품목 행 다섯 개가 보여야 합니다.

```text
페퍼르니인집스 29,000 1 29,000
토마ㅌ마스 14000 1 14,000
수제돈가스 13,000 1 13,000
새우 실시치리 14,000 1 14,000
콜라 2,000 3 6,000
```

품목명이 틀린 것은 OCR 인식 문제이고, 네 값이 같은 줄에 놓이는 것은 문서 구조
복원 문제입니다. 두 문제를 구분해서 관찰합니다.

![영수증 영역을 구조로 나누는 그림](assets/03/02_structure_map.svg)

### 4. 결과를 저장합니다

`clean_receipt.json`에는 원문 행과 다음 영역이 함께 저장됩니다.

- `date`: 날짜 후보
- `items`: 품목 행 후보
- `total`: 합계 후보
- `other`: 아직 분류하지 못한 행

데이터를 만들려면 원문을 보존한 채 날짜·품목·합계의 관계를 다시 묶어야 합니다.
