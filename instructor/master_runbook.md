# 강사용 마스터 런북

> 대상: 강사 1명, 수강생 20명, Python 문법을 모두 외우지는 못하지만 코드를 읽고 실행할 수 있는 일반 실무자

## 이 강의가 약속하는 결과

수강생 한 명이 공개 한국 영수증 한 장을 `OCR → 구조화 → 검증 → 사람 승인 → Excel`로 완주하고, 견적서·신청서·거래명세서 중 첫 PoC 후보 하나를 설명한다.

강의가 끝날 때 모든 수강생에게 다음 핵심 파일이 있어야 한다.

- `receipt_result.xlsx`
- `final_document_ai_app.zip`
- `poc_candidate_card.md`

“모델을 봤다”가 아니라 “내가 실행했고, 실패를 구분했고, 승인 후 파일을 만들었다”가 통과 기준이다.

### 전체 체류 8시간이 계약이라면

각 교시를 50분으로 압축하고 점심 50분, 휴식 10분 세 번, 오프닝·마감을 10분씩 둔다. 공지된 8개 주제는 유지하되 선택 VLM 시연, 추가 문서 코딩, 긴 질의응답을 줄인다. 60분 운영안과 8시간 체류안을 혼용하지 않는다.

## 20명·강사 1명의 자리 운영

- 수강생은 **1인 1문제·1인 1산출물**을 유지한다.
- 좌석은 5개 복구 라인으로만 나눈다. 한 줄 4명은 진행 표시와 오류 전파를 돕지만 결과물을 공동 제작하지 않는다.
- 각 노트북 마지막 `CHECKPOINT 1/1 PASS`를 화면에 띄운다.
- 수강생은 손 또는 메모지로 상태를 표시한다.
  - 초록: 산출물 생성
  - 노랑: 실행 중 또는 3분 이내 오류
  - 빨강: 3분 초과·개인정보·반복 오류
- 같은 오류가 3명에게 나오면 개인 대응을 중지하고 전체 화면에서 한 번 해결한다.
- 같은 모델 설치 오류가 3명에게 나오면 전원 `PREPARED_FALLBACK`으로 전환한다.
- 빠른 수강생은 다른 사람 코드를 대신 고치지 않고 원본 근거·검증 규칙·PoC 카드 품질을 보강한다.

## 교시 공통 60분 리듬

| 구간 | 시간 | 강사 행동 | 수강생 증거 |
| --- | ---: | --- | --- |
| 문제와 완성 결과 | 0~5분 | 원본과 이번 산출물을 나란히 보여 줌 | 오늘 파일명 말하기 |
| 개념 | 5~11분 | 한 문장·한 비유·한 오류 사례 | 짝에게 20초 설명 |
| 첫 실행 | 11~18분 | 정상 화면과 실행 모드 시연 | 같은 화면 확인 |
| 개별 실습 | 18~43분 | 5개 복구 라인을 순회 | 코드 실행·값 비교 |
| 실패·복구 | 43~52분 | 오류 1회, 3분 전환 기준 | 복구 경로 실행 |
| 산출물 검사 | 52~57분 | 파일 존재·내용 한 곳 확인 | `CHECKPOINT PASS` |
| 연결 | 57~60분 | 다음 교시가 이 파일을 어떻게 쓰는지 보여 줌 | 파일 다운로드 |

개념 설명이 11분을 넘으면 실습 시간을 침범한 것이다. 0~12 지도는 1교시 참고 포스터로만 사용한다.

## 교시 시작에 그대로 말할 문장

1. “오늘 외울 것은 제품 이름이 아니라 네 역할입니다. 읽기, 구조화, 검증, 업무 연결입니다.”
2. “실행 전에 모드부터 보세요. LIVE는 지금 실행한 결과, PREPARED는 검수된 복구 결과입니다.”
3. “정제는 없는 값을 만드는 일이 아닙니다. 원문을 보존한 채 관계를 다시 묶는 일입니다.”
4. “OCR+규칙과 VLM은 서로 다른 초안 경로입니다. 어느 쪽이든 원본 근거가 없으면 null로 둡니다.”
5. “파일을 올렸는데 화면 값이 달라지지 않으면 앱이 연결된 것이 아닙니다.”
6. “처리 뒤 파일명, 실행 모드, 원문, JSON이 모두 바뀌어야 실제 처리입니다.”
7. “오류가 없다는 것과 사람이 승인했다는 것은 다른 상태입니다. 수정했다면 반드시 다시 검증합니다.”
8. “문서 종류가 바뀌어도 흐름은 같고, 필드와 검증 규칙이 달라집니다.”

공통 보안 문장:

> “Colab은 외부 클라우드입니다. 오늘은 제공된 비식별 샘플만 사용하고, 개인·회사 문서는 승인 없이 업로드하지 않습니다.”

## 모델 다운로드와 네트워크 운영

- T-48시간에 강사 계정으로 새 Colab 런타임에서 2교시 LIVE 경로를 실행한다.
- 결과를 `instructor/preflight_checklist.md`에 기록한다. 실행하지 않았다면 “미검증”으로 남긴다.
- 20명이 동시에 다운로드하지 않도록 5개 복구 라인을 1분 간격으로 시작한다.
- 1차 웨이브에서 오류가 3명 이상이면 나머지 웨이브를 시작하지 않고 준비 결과로 전환한다.
- VLM은 강사 시연 1회만 허용한다. 승인된 계정·비식별 샘플·예산 상한이 없으면 녹화 또는 준비 결과로 대체한다.

## Colab 교시 간 파일 인계

Colab 링크마다 런타임과 `/content` 파일시스템이 새로 열릴 수 있다고 가정한다.

1. 2교시 종료: `lesson02_ocr_outputs.zip` 다운로드·압축 해제 확인
2. 3교시 시작: ZIP 안의 `ocr_result.json` 업로드 → 종료 시 `clean_receipt.json` 다운로드
3. 4교시 시작: `clean_receipt.json` 업로드 → 종료 시 `receipt.json` 다운로드
4. 7교시 시작: `receipt.json` 업로드 → 값 수정·재검증·승인 후 `receipt_result.xlsx`와 최종 앱 ZIP 다운로드

진행 현황판에는 파일 존재뿐 아니라 `PREVIOUS_LESSON` 또는 `PREPARED_FALLBACK`을 기록한다. 파일 선택에서 3분을 넘기면 노트북의 `USE_PREPARED_INPUT=True`로 전환하되, 자신의 파일을 이어 쓴 것처럼 말하지 않는다.

## 개인정보 사고 대응

개인정보·회사 비밀·API 키가 화면에 나오면 설명보다 중지가 먼저다.

1. 프로젝터 공유를 중지한다.
2. 공개 링크·터널이 있다면 닫는다.
3. 해당 Colab 출력과 런타임 파일을 삭제하고 런타임을 종료한다.
4. 공유 저장소·다운로드 폴더에 남았는지 확인한다.
5. 조직의 사고 보고 절차를 따른다.
6. 해당 자료를 수업 샘플이나 화면 캡처로 재사용하지 않는다.

## 강의 종료 전 10분

- 20명 모두 `receipt_result.xlsx`의 세 시트를 연다.
- 20명 모두 최종 앱에서 총액을 일부러 틀려 다운로드가 차단된 뒤 복구되는 것을 확인한다.
- 승인자·승인 시각·원문 근거를 한 곳씩 찾는다.
- 20명 모두 PoC 카드의 오류 영향과 사람 검토자를 읽는다.
- `outcome_evidence_plan.md`의 종료 지표를 집계하고 교육담당자 보고 초안을 채운다.
- 개인·회사 문서가 런타임에 남지 않았는지 확인한다.
- 전체 정답 코드와 복습 경로를 안내한다.
