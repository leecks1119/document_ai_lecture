# Document AI와 생성형 AI를 활용한 문서 데이터 추출 및 자동화 실습

> 강사·교재 설계자용 커리큘럼 원전입니다. 수강생용 과정 안내는 루트 `README.md`를 사용합니다.

> Python을 한 번 사용해 본 일반 실무자가 실제 영수증 한 장으로 작은 Document AI 프로토타입을 완성하는 하루 과정

## 1. 과정의 핵심 메시지

> “영수증으로 해보니 원리를 알겠다. 우리 회사의 견적서나 신청서도 이런 식으로 자동화해볼 수 있겠는데?”

이 과정은 모델 이름을 많이 외우는 수업이 아니다. 학습자는 식별정보를 가린 영수증 한 장을 직접 판독하고, 필요한 값을 JSON으로 구조화하고, 원문과 대조해 검증한 뒤 `receipt_result.xlsx`로 내려받는다. 마지막에는 같은 파이프라인을 견적서·신청서·거래명세서 중 한 가지에 적용할 수 있는지 검토한다.

과정을 마친 학습자는 다음 수준에 도달한다.

- 실제 문서 한 장으로 작동하는 작은 프로토타입을 직접 만들 수 있다.
- 자동화할 필드, 입력 품질, 오류 영향, 사람 검토 방법을 설명할 수 있다.
- 우리 업무에서 작게 시험할 Document AI PoC 후보를 검토할 수 있다.

## 2. 과정 개요

| 항목 | 내용 |
| --- | --- |
| 교육 시간 | 하루 8시간, 8교시 연속 과정 |
| 교육 대상 | Python을 한 번 사용해 봤지만 문법을 모두 알지는 못하는 일반 실무자 |
| 교육 인원 | 20명 |

### 핵심 실습 흐름

```text
식별정보를 가린 영수증 한 장
  → OCR 또는 준비 결과
  → 키-값·반복 행 정리
  → 업무용 JSON
  → 필수값·형식·합계 검증
  → 사람의 원문 확인·값 수정·재검증
  → receipt_result.xlsx
```

## 3. 운영 원칙

### 3.1 개념 10%, 실습 90%

- 1교시는 용어와 전체 절차를 정확히 설명하기 위해 최대 28분을 사용한다.
- 2~8교시의 새 개념 설명은 교시당 최대 6분으로 제한한다.
- 새 핵심 개념은 최대 3개다.
- 학습자가 직접 작성하는 코드는 10~15줄 이내로 제한한다.
- 나머지는 시작 코드, 빈칸, 힌트, 전체 정답으로 제공한다.
- 정답지는 처음부터 공개하며, 학습자는 실행·비교·수정·검증에 집중한다.

### 3.2 한 사람, 한 문서, 한 문제

- 기본 경로는 전원이 같은 공개·비식별 한국 실물 영수증을 사용한다.
- 빠른 학습자는 조직 정책을 확인하고 식별정보를 완전히 가린 점심·커피 영수증 또는 사진첩 영수증 한 장으로 다시 실행할 수 있다.
- 한 번에 문서 한 장만 처리한다.
- 기본 문제는 영수증으로 통일하고, 빠른 학습자만 다른 문서에 도전한다.

### 3.3 실패해도 수업은 계속

- 각 교시 노트북에는 이전 교시 산출물의 완성 복구본을 넣는다.
- 실제 OCR은 3분 동안 시도하고 해결되지 않으면 준비된 결과로 전환한다.
- 준비 결과와 실제 실행 결과를 화면에서 명확히 구분한다.
- 한 학습자의 설치 문제 때문에 전체 수업을 멈추지 않는다.

### 3.4 개인정보와 외부 전송

- 카드번호, 승인번호, 현금영수증 번호, 전화번호, 회원번호 등은 촬영 또는 업로드 전에 가린다.
- 개인 영수증과 회사 문서는 공개 웹앱 주소나 외부 API에 올리지 않는다.
- 필수 실습은 공개 터널 없이 Colab의 Streamlit AppTest로 확인한다.
- 학습자가 실제 영수증으로 OCR을 실행한 뒤에는 셀 출력과 런타임 파일을 삭제한다.
- 상용 VLM은 강사 계정과 비식별 샘플로 한 번만 시연한다.

## 6. 교시별 전달 의도

### 1교시. 한국 영수증으로 구분하는 OCR·VLM·Document AI

학습자는 기술 이름보다 역할과 경계를 먼저 이해한다. OCR은 이미지에서 텍스트를 인식하고, VLM은 이미지와 언어를 함께 다루는 Multimodal AI의 한 종류다. 이 과정에서는 Document AI를 분류·OCR·레이아웃·필드 추출·정규화 같은 기술·제품 역량으로, IDP를 여기에 접수·검증·예외·사람 확인·업무 연결·평가를 결합한 운영 범위로 구분한다. 용어는 공급자에 따라 겹칠 수 있음을 명시한다.

0~12 단계는 암기 목록이 아니라 전체 참조 지도로 사용한다. 강사가 완성 Excel을 2~3분 미리 보여 준 뒤, 학습자는 모델을 설치하지 않고 준비된 실제 영수증 결과에서 원문·정규화 값·근거·검증·처리 결정을 추적한다. Excel 직접 생성은 7교시에 수행한다.

### 2교시. OCR 기반 텍스트 추출 실습

공개 비식별 영수증으로 PP-OCRv5 Korean을 실행한다. 텍스트·위치·신뢰도를 보면서 합계와 날짜가 원본과 같은지 확인한다. 신뢰도는 정답 확률이 아니라는 점을 실제 오인식에서 느끼게 한다. 개인 영수증은 완전 비식별화한 선택 반복만 허용한다. 3분 안에 실행되지 않으면 같은 구조의 준비 결과로 전환한다.

### 3교시. 문서 구조 이해 및 추출 결과 정제

필수 실습은 OCR 원문 보존, 바운딩 박스의 y·x 좌표에 따른 읽기 순서 복원, 키-값, 반복 품목 행 재구성에 집중한다. Excel·Word·PPT 원본은 구조 파서, 텍스트 PDF는 텍스트층을 먼저 사용할 수 있지만 표 캡처·사진·스캔은 픽셀만 남는다는 차이는 강사 비교로 짧게 체험한다. 복잡한 표 복원 코드는 완성 예제로만 보여 준다.

### 4교시. 멀티모달·생성형 AI 기반 핵심 정보 추출

강사가 PaddleOCR-VL 1.6 또는 상용 VLM을 비식별 샘플로 한 번 시연한다. 학습자 필수 코드는 3교시 OCR 텍스트에 규칙을 적용한 기준선이며 이를 VLM 결과라고 부르지 않는다. 별도의 준비 VLM 구조 예시는 `engine=not_executed`로 표시한다. 두 결과에서 각 값의 원문 근거를 확인하고 찾을 수 없으면 `null`로 둔다.

### 5교시. 문서 자동화 웹 애플리케이션 기본 구현

새 AI 모델을 만드는 시간이 아니라 이미 만든 Python 함수에 Streamlit 화면을 붙이는 시간이다. Colab에서 `app_05.py`를 만들고 Streamlit AppTest로 파일 입력·버튼·결과 영역을 검사한 뒤 Colab 내부 미리보기에서 직접 조작한다. 공개 서버나 터널은 열지 않는다.

### 6교시. OCR 및 정보 추출 기능 연동

학습자가 직접 연결하는 필수 경로는 하나다.

```text
파일 → OCR 또는 준비 텍스트 → 공간 순서 복원 → 추출 함수 → JSON
```

Office 원본, 텍스트 PDF, 표 캡처, 사진에 맞는 입력 라우팅은 완성 도우미 함수로 제공한다. 실제 처리인지 준비 결과인지, 어느 단계에서 실패했는지를 화면에 표시하고 조용한 자동 전환은 하지 않는다. 실제 PP-OCRv5 LIVE 44토큰 회귀 사례가 공간 복원 뒤 합계와 5개 품목을 만드는지 자동 검사한다.

### 7교시. 추출 결과 검증 및 데이터 저장

필수값, 날짜 형식, 금액 형식, 품목 합계를 검사한다. 최종 앱에서 학습자가 상호명·날짜·총액과 품목 표를 수정하고 다시 검증한다. 오류가 있으면 Excel 생성을 막고, 경고는 사람 확인 대상으로 표시한다. Excel에는 원문·정제값·최종값·검토 상태를 남기며 `=`, `+`, `-`, `@`로 시작하는 추출 문자열이 수식으로 실행되지 않게 보호한다.

### 8교시. 실무 적용 시나리오 설계 및 최종 정리

강사는 비식별 실물 형태의 견적서·신청서·거래명세서 샘플 구현과 Excel·Word·PDF·PPT 실제 파일을 제공한다. 학습자는 내부 구조 검사 결과를 보고 직접 파싱과 이미지 판독의 차이를 체험한다. 세 문서 중 하나만 골라 영수증 파이프라인에서 바뀌는 필드와 검증 규칙을 찾고, 자기 점수·검토자·중단 조건을 작성한다. 발주서는 예시와 선택지에서 제외한다.

| Word 원본 | 문단·표 구조 | 화면에 보이는 배치와 내부 구조가 다를 수 있다. |
| PPT 원본 | 텍스트 상자·도형 구조 | 읽기 순서가 화면 위치와 다를 수 있다. |
| 텍스트 PDF | 텍스트층 | 보이는 글자를 OCR로 다시 읽을 필요가 없을 수 있다. |
| 스캔 PDF·사진·표 캡처 | 픽셀 | OCR 또는 VLM으로 글자와 관계를 복원해야 한다. |

필수 구현은 영수증 이미지 한 장에 집중한다. 다른 형식은 강사 시연과 완성 코드로 체험해 60분 교시의 범위를 지킨다.

## 8. 강사 시연과 제공 샘플

| 문서 | 시연 목적 | 주요 필드 예시 |
| --- | --- | --- |
| 영수증 | 전체 기본 파이프라인 | 상호명, 거래일, 품목, 합계 |
| 견적서 | 표와 합계 검증 확장 | 공급자, 견적일, 품목, 공급가액, 총액 |
| 신청서 | 키-값·선택 항목 확장 | 신청자, 신청일, 신청 유형, 연락 수단 |
| 거래명세서 | 반복 행과 합계 확장 | 공급자, 거래일, 품목, 수량, 금액 |

강사는 각 문서의 비식별 실물 형태 샘플, 실행 코드, 예상 결과를 제공한다. 학습자는 영수증 외 문서의 코드를 새로 작성하지 않고 필드와 검증 규칙의 차이를 관찰한다.

## 9. 완료 기준

- OCR·VLM·Document AI의 역할과 처리 과정을 설명할 수 있다.
- 식별정보를 가린 실제 영수증 한 장에서 OCR 또는 준비 결과를 얻을 수 있다.
- 상호명·날짜·품목·합계를 JSON으로 구조화하고 원문과 대조할 수 있다.
- 검증 오류가 있는 결과의 Excel 다운로드를 차단할 수 있다.
- 정상 결과를 `receipt_result.xlsx`로 내려받을 수 있다.
- 견적서·신청서·거래명세서 중 하나의 PoC 적합성과 중단 조건을 설명할 수 있다.
- 학습자 API 키나 결제 없이 필수 경로를 완료할 수 있다.
