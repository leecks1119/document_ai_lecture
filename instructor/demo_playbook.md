# 강사용 시연 플레이북

## 시연 원칙

- 먼저 완성 결과를 보여 주고, 그 결과를 만드는 최소 경로만 연다.
- 실제 실행과 준비 결과를 같은 색·같은 문구로 보여 주지 않는다.
- 코드보다 파일명·실행 모드·원문·JSON·검증·승인·Excel을 가리킨다.
- 모든 시연은 저장소의 공개·합성 샘플로 한다.

## 오프닝 7분

### 화면 순서

1. 공개 한국 영수증
2. `ocr_boxes.png`
3. `receipt.json`의 `total_amount`와 evidence
4. 검증 오류 한 건
5. Streamlit 앱의 실행 모드
6. `receipt_result.xlsx` 세 시트

### 말하기

> “오늘은 AI 모델을 구경하는 수업이 아닙니다. 이 영수증 한 장이 검증된 Excel 한 줄이 되는 과정을 여러분 손으로 완주합니다.”

> “화면이 멋져도 업로드한 파일과 결과가 연결되지 않으면 프로토타입이 아닙니다. 파일명, 실행 모드, 원문, JSON이 함께 바뀌는지 보겠습니다.”

## 2교시 LIVE OCR 시연

1. `RUN_LIVE_OCR=True`를 보여 준다.
2. 3분 타이머를 시작한다.
3. `LIVE`가 뜨면 bbox와 합계 줄을 가리킨다.
4. 오류가 나면 오류 문구를 읽고 `PREPARED_FALLBACK` 결과의 전환 사유를 보여 준다.

말하기:

> “복구 결과는 실패를 숨기는 가짜 성공이 아닙니다. 네트워크 문제와 오늘 배울 원리를 분리해 수업을 계속하는 장치입니다.”

## 4교시 VLM 시연 1회

시연 전 확인:

- 승인된 비식별 샘플
- 승인된 계정
- API 또는 GPU 예산 상한
- 화면에 키·토큰이 보이지 않음

시연 순서:

1. 입력 이미지
2. 모델의 Markdown·블록 결과
3. 업무 JSON
4. 원본 근거
5. 틀리거나 없는 값의 `null`

시연 실패 시 재시도하지 않는다. 준비 결과의 provenance와 “현재 실행에서 호출한 결과가 아님” 문구를 보여 준다.

## 5·6교시 앱 시연

### 5교시

- 파일을 올린다.
- 파일명과 바이트 수가 바뀌는지 보여 준다.
- 준비 결과 버튼을 눌러 화면 뼈대를 확인한다.

### 6교시

- 업로드 없이 LIVE 버튼을 눌러 `INPUT_ERROR`를 보여 준다.
- 공개 샘플 준비 결과 버튼으로 `PREPARED_FALLBACK`을 보여 준다.
- 실제 업로드 경로는 `run_live_ocr(uploaded)`가 실행된다는 코드를 한 곳만 보여 준다.

말하기:

> “오류 화면도 제품의 일부입니다. 자동화가 실패했을 때 무엇을 보여 주고 어디로 보내는지가 실무 품질을 결정합니다.”

## 7교시 승인·Excel 시연

1. `PENDING` 상태에서 Excel이 없는 것을 확인한다.
2. 원본 상호명·날짜·품목·총액을 대조한다.
3. 공개된 전체 정답 `REVIEW_RECORD`를 실행한다.
4. Excel의 `검토_요약`, `품목`, `원문_근거`를 연다.
5. `decision`, `reviewer`, `reviewed_at`, `change_reason`을 가리킨다.

말하기:

> “검증 통과는 컴퓨터 규칙을 통과한 상태입니다. 사람 승인은 책임자가 원본을 확인했다는 별도 기록입니다.”

## 8교시 형식 비교 시연

- Excel: `품목!E2` 수식과 병합 제목을 보여 준다.
- Word: 신청서 본문이 텍스트가 아니라 이미지 한 장임을 보여 준다.
- PDF: 텍스트 선택 가능 여부와 한 페이지를 확인한다.
- PPT: 그룹·읽기 순서·발표자 노트가 이미지 캡처에 남지 않는다고 설명한다.
- 표 캡처: 셀 좌표가 사라지고 픽셀만 남는다는 점을 보여 준다.

마무리:

> “우리 회사 문서도 같은 흐름으로 시작할 수 있습니다. 먼저 한 종류, 한 장, 몇 개 필드, 사람 검토가 가능한 범위로 줄이세요.”
