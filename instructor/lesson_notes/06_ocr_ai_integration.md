# 6교시 강사 노트

## 전달할 한 문장

처리 뒤 파일명·처리 방식·원문·JSON이 모두 바뀌어야 실제 처리다.

## 60분 운영

| 시간 | 행동 | 예상 증거 |
| ---: | --- | --- |
| 0~6 | 직접 읽기·읽기 실패·수업용 예제 화면 비교 | 세 상태 |
| 6~11 | OCR/VLM 선택 기준 | 고정 순서 아님 |
| 11~20 | `read_receipt_now` 한 함수 시연 | 업로드 bytes 사용 |
| 20~32 | 앱 생성·AppTest | `app_06.py` |
| 32~38 | 업로드 없이 직접 읽기 | 파일 선택 안내 |
| 38~44 | 수업용 예제 버튼 | 현재 사진 결과가 아님 |
| 44~50 | 44토큰 실제 OCR 기록 재검사 | 합계 76000·5품목 |
| 50~56 | 직접 실행 확인 필드 빈칸·미리보기 | 자기 답·직접 조작 |
| 56~60 | 검증 입력 연결 | JSON |

## 그대로 말하기

> “오류 화면도 제품의 일부입니다. 실패를 숨기지 않아야 다음 행동을 정할 수 있습니다.”

## 금지

- 업로드 오류 뒤 관련 없는 준비 결과를 자동 성공처럼 표시
- 현재 사진을 분석하지 않았다는 문구 숨김
- 개인 문서로 직접 OCR 경로 재시도

## 복구

직접 읽기 오류는 그대로 보존한 뒤 사용자가 `수업용 예제로 계속하기` 버튼을 누른다. PaddleOCR 설치 오류가 3명에게 나오면 전원 예제 경로로 전환한다.

## 종료 조건

`app_06.py`에 `read_receipt_now`, 공간 순서 복원, 세 가지 쉬운 상태 문구가 있고 AppTest가 통과한다. 내부 JSON에는 기술 기록값 `OCR_ERROR`, `COURSE_EXAMPLE`이 남는다. 실제 44토큰 기록이 합계 76,000원·품목 5개로 복원된다.
