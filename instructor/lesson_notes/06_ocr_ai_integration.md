# 6교시 강사 노트

## 전달할 한 문장

처리 뒤 파일명·실행 모드·원문·JSON이 모두 바뀌어야 실제 처리다.

## 60분 운영

| 시간 | 행동 | 예상 증거 |
| ---: | --- | --- |
| 0~6 | LIVE·LIVE_ERROR·PREPARED 화면 비교 | 세 상태 |
| 6~11 | OCR/VLM 선택 기준 | 고정 순서 아님 |
| 11~20 | `run_live_ocr` 한 함수 시연 | 업로드 bytes 사용 |
| 20~35 | 앱 생성·AppTest | `app_06.py` |
| 35~43 | 업로드 없이 LIVE 오류 | INPUT_ERROR |
| 43~50 | 준비 결과 버튼 | 명시적 복구 |
| 50~57 | 실제 파일 경로 또는 녹화 | LIVE 증거 |
| 57~60 | 검증 입력 연결 | JSON |

## 그대로 말하기

> “오류 화면도 제품의 일부입니다. 실패를 숨기지 않아야 다음 행동을 정할 수 있습니다.”

## 금지

- 업로드 오류 뒤 관련 없는 준비 결과를 자동 성공처럼 표시
- `PREPARED_FALLBACK` 문구 숨김
- 개인 문서로 LIVE 경로 재시도

## 복구

LIVE 오류는 그대로 보존한 뒤 사용자가 준비 결과 버튼을 누른다. PaddleOCR 설치 오류가 3명에게 나오면 전원 복구한다.

## 종료 조건

`app_06.py`에 `run_live_ocr`, `LIVE_ERROR`, `PREPARED_FALLBACK`이 있고 AppTest가 통과한다.
