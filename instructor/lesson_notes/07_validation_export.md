# 7교시 강사 노트

## 전달할 한 문장

오류가 없다는 것과 사람이 승인했다는 것은 다른 상태이며, 사람이 값을 바꾸면 다시 검증해야 한다.

## 60분 운영

| 시간 | 행동 | 예상 증거 |
| ---: | --- | --- |
| 0~6 | valid·warnings·errors 병렬 판정 설명 | 순차 단계 아님 |
| 6~13 | 필수값·자료형·품목·합계·포함세액·근거 | 여섯 규칙 |
| 13~23 | 정상과 오류 데이터 실행 | 오류 메시지 |
| 23~31 | 수식 주입 예시 | 공백 뒤 `=` 보호 |
| 31~38 | PENDING 차단 | 파일 없음 |
| 38~44 | 검토자·메모 빈칸 작성 | 개인 승인 기록 |
| 44~50 | 최종 앱에서 총액을 틀리게 수정 | 다운로드 차단 |
| 50~55 | 정상값 복구·재검증·승인 | Excel 생성 |
| 55~58 | 세 시트·최종 앱 ZIP 확인 | 승인·품목·근거 |
| 58~60 | PoC 적용 예고 | 오류 영향 |

## 그대로 말하기

> “검증 통과는 컴퓨터 규칙을 통과한 상태입니다. 사람 승인은 책임자가 원본을 확인했다는 별도 기록입니다.”

> “사람이 고친 값도 정답이라고 가정하지 않습니다. 수정한 순간 검증을 다시 통과해야 합니다.”

> “오늘 부가세 6,906원은 76,000원 안에 이미 포함된 내역입니다. 다시 더하면 이중 계산입니다.”

## 시연할 오류

- 필수 상호명 누락
- Boolean 금액
- 수량×단가 불일치
- 품목·조정 후 합계 불일치
- 포함 부가세를 `adjustments.tax`에 다시 더한 이중 계산
- 원본 근거 없음 경고
- 앞 공백·탭 뒤 수식 시작 문자
- 최종 앱에서 총액을 999로 수정한 뒤 합계 불일치와 다운로드 차단

## 복구

오류가 남았으면 승인 셀을 실행하지 않는다. 전체 정답을 사용해도 `PENDING` 차단 셀을 먼저 통과해야 한다.

## 종료 조건

새 런타임에서는 `receipt.json` 업로드를 먼저 확인한다. 전원 최종 앱에서 잘못된 수정값 차단→정상값 복구→재검증→승인을 거친다. `receipt_result.xlsx` 세 시트와 `final_document_ai_app.zip`을 확인한다.
