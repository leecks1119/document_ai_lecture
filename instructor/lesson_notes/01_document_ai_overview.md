# 1교시 강사 노트

## 전달할 한 문장

문서 자동화는 읽기·구조화·검증·사람 확인·업무 연결의 과정이다.

## 60분 운영

| 시간 | 행동 | 예상 증거 |
| ---: | --- | --- |
| 0~5 | 공개 영수증과 완성 Excel을 나란히 보여 줌 | “오늘 이 사이를 만든다” |
| 5~11 | OCR·VLM·Document AI·IDP 네 역할 설명 | 수강생 20초 설명 |
| 11~18 | 0~12 지도를 참고 포스터로 훑음 | 암기하지 않는다고 확인 |
| 18~28 | 합계 76,000의 원본 근거 찾기 | 합계 줄 지목 |
| 28~47 | Colab trace 작성·실행 | roles 4개 |
| 47~53 | 높은 신뢰도라도 승인 아님을 질문 | 원본 대조 답 |
| 53~57 | 산출물 확인 | trace JSON |
| 57~60 | 2교시 LIVE OCR 연결 | 다음 파일명 말하기 |

## 그대로 말하기

> “오늘 외울 것은 제품 이름이 아니라 네 역할입니다. 읽기, 구조화, 검증, 업무 연결입니다.”

> “0~12는 시험 범위가 아니라, 실무에서 빠뜨릴 질문이 없는지 보는 체크 지도입니다.”

## 확인 질문과 정답

- OCR은 무엇을 읽나? → 글자와 위치
- VLM 초안이 바로 정답인가? → 아니오, 근거·스키마·검증 필요
- Document AI와 IDP의 차이는? → IDP는 사람 승인·예외·업무 연결·운영까지 포함

## 오개념 복구

“OCR, VLM, Document AI 중 무엇이 제일 좋은가요?”라고 물으면 경쟁 순위가 아니라 범위와 선택 문제라고 답한다. 단순 문서는 OCR, 복잡한 구조는 VLM을 검토하지만 어느 쪽도 사람 승인과 운영을 대신하지 않는다.

## 전환 기준

이미지 로딩 실패 3명 이상이면 로컬 공개 영수증 이미지를 화면에 띄우고 trace 코드만 실행한다.

## 종료 조건

전원 `receipt_pipeline_trace.json` 생성. 최소 15명이 네 역할을 한 문장씩 말할 수 있어야 한다.
