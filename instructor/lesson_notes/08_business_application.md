# 8교시 강사 노트

## 전달할 한 문장

문서 종류가 바뀌어도 흐름은 같고, 필드·검증 규칙·오류 영향이 달라진다.

## 60분 운영

| 시간 | 행동 | 예상 증거 |
| ---: | --- | --- |
| 0~8 | 견적서·신청서·거래명세서 사진 비교 | 세 구조 |
| 8~15 | Office ZIP 다운로드·Excel·Word·PDF·PPT 직접 열기 | 내부 구조·형식 예외 |
| 15~22 | 표 캡처가 셀 구조를 잃는 과정 | 픽셀 설명 |
| 22~30 | PoC 기준 다섯 항목 | 점수표 |
| 30~47 | 수강생 1인 1후보 카드 작성 | 개인 카드 |
| 47~53 | 3명 예시 공유 | 필드·규칙·위험 |
| 53~57 | 범위를 한 종류·한 장으로 축소 | GO_SMALL/REVIEW |
| 57~60 | 최종 핵심 파일 확인 | Excel·최종 앱·카드·문서별 코드 ZIP |

## 그대로 말하기

> “우리 회사 문서도 같은 흐름으로 시작할 수 있습니다. 먼저 한 종류, 한 장, 몇 개 필드, 사람 검토가 가능한 범위로 줄이세요.”

## 형식 시연 포인트

- Excel: 수식·병합·숨김·서식은 이미지 OCR로 사라질 수 있다.
- Word: 이 샘플은 본문이 이미지 한 장이다.
- PDF: 텍스트층과 스캔이 섞일 수 있다.
- PPT: 그룹·읽기 순서·노트는 캡처에 남지 않는다.
- 표 캡처: 행·열 위상을 다시 복원해야 한다.

## 빠른 수강생

다른 수강생 코드를 대신 고치지 않는다. 선택 문서의 실패 예시, 검토자, 중단 조건, 삭제 시점을 보강한다.

## 종료 조건

모든 수강생이 자기 `poc_candidate_card.md`를 만든다. 카드에
입력 문서·필드·규칙·자기 점수·오류 영향·사람 검토자·저장·중단 조건이
있어야 한다. `office_format_samples.zip`의 네 파일을 실제로 한 번씩 열고,
`business_document_code_examples.zip`에 견적서·신청서·거래명세서용 코드와
JSON 예제가 모두 있는지 확인한다.
