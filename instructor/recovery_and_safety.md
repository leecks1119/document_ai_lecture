# 강사용 복구·안전 대응

## 20명 수업의 복구 원칙

수강생 화면을 대신 조작하기 전에 다음 순서를 공통으로 적용한다.

1. 오류 메시지를 함께 읽는다.
2. 같은 셀을 한 번만 다시 실행한다.
3. 전체 시도가 3분을 넘으면 실행을 중지한다.
4. 준비 결과를 선택하고 필요한 셀을 위에서 아래로 다시 실행한다.
5. AppTest 실패는 전체 정답을 불러온 뒤 처리 함수를 셀에서 직접 호출한다.
6. 해당 교시 체크포인트와 산출물 또는 ZIP 묶음이 만들어지면 다음 교시로 이동한다.

준비 결과는 화면과 산출물에 `COURSE_EXAMPLE`으로 표시한다. 실제 모델 결과로 설명하지 않는다. `MOCK`은 합성 함수·데이터를 뜻할 때만 사용하고, 검수된 공개 영수증 replay와 섞지 않는다.

## 개인정보·비밀 노출 대응

Google Colab도 외부 클라우드이며 업로드는 외부 전송이다. 조직 승인 없는 개인·회사 문서는 처음부터 올리지 않는다. 실제 개인정보, 회사 문서, API 키가 노출되면 실습을 즉시 중지한다.

1. 공개 화면·터널·공유 링크를 닫는다.
2. Colab 출력과 런타임 파일을 삭제하고 런타임을 종료한다.
3. Git 변경이나 공유 저장소에 남았는지 확인한다.
4. 조직의 보안·개인정보 사고 보고 절차를 따른다.
5. 해당 자료를 다시 시연하거나 교재 자산으로 저장하지 않는다.

법률 해석이나 조직 정책을 교재의 일반 규칙으로 단정하지 않는다. 실제 적용 전에는 업무 소유자·보안·개인정보 담당자에게 외부 전송, 접근, 보존, 삭제 기준을 확인한다.

## 공개 자료와 유지보수

- 학생 교재에는 채택한 샘플의 출처와 라이선스만 짧게 남긴다.
- 라이선스 비교, 원본 해시, 메타데이터 제거, 채택·제외 판단은 `docs/public_receipt_datasets.md`에서 관리한다.
- 버전·지원 범위·가격·보안 정책은 기준일 현재 공식 자료로 재확인한다.
- 검증 기록은 `docs/verification_report.md`, 개편 상태는 `docs/rebuild_status.md`에서 관리한다.
