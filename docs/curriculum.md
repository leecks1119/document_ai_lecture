# Document AI와 생성형 AI를 활용한 문서 데이터 추출 및 자동화 실습

> 초급자를 위한 OCR, 생성형 AI, Codex 기반 문서 자동화 미니 앱 제작 실습

## 1. 과정 개요

| 항목 | 내용 |
| --- | --- |
| 교육 시간 | 총 8시간(8교시) |
| 교육 대상 | Python 기초 경험이 있는 Document AI 입문자 |
| 개발 도구 | Codex |
| 실습 언어 | Python 3.12.9 |
| UI 프레임워크 | Gradio 권장, Streamlit 대체 가능 |
| 실습 환경 | 로컬 PC, `pip` + `venv` |
| 최종 결과물 | 문서 업로드부터 CSV 다운로드까지 가능한 Document AI 미니 앱 |

이 과정은 특정 OCR 라이브러리의 사용법보다 문서 자동화의 전체 흐름을 익히는 데 초점을 둔다. 교육생은 영수증, 신청서, 견적서와 같은 문서를 입력으로 받아 텍스트를 추출하고, 필요한 정보를 JSON으로 구조화한 뒤, 결과를 검증하고 CSV로 저장하는 과정을 단계별로 구현한다.

### 핵심 실습 흐름

```text
문서 업로드
    ↓
OCR 텍스트 추출
    ↓
생성형 AI 프롬프트를 활용한 JSON 구조화
    ↓
필수값·날짜·금액 형식 검증
    ↓
표 확인 및 CSV 다운로드
```

OCR 설치나 모델 다운로드가 실패해도 전체 과정을 계속 진행할 수 있도록 샘플 OCR 결과와 mock 추출 결과를 제공한다. 실제 생성형 AI API 연결은 선택 실습으로 다루며, API 키가 없어도 핵심 실습을 완료할 수 있게 구성한다.

## 2. 교육 대상 및 선수 지식

### 교육 대상

- Document AI, OCR, 생성형 AI 기반 정보 추출을 처음 접하는 학습자
- Python 문법과 함수의 기본 개념을 알고 있는 학습자
- 영수증, 신청서, 견적서, 계약서, 점검표 등 반복 문서 업무를 자동화하고 싶은 실무자
- 모든 코드를 직접 작성하기보다 Codex와 협업하여 기능을 만들고 수정하는 방식을 경험하고 싶은 학습자

### 권장 선수 지식

- Python 변수, 조건문, 함수, 리스트, 딕셔너리의 기초
- 터미널에서 명령어를 실행하고 파일을 열어 본 경험
- JSON과 CSV의 용도를 이해할 수 있는 수준의 데이터 기초 지식

OCR, Gradio, 생성형 AI API 사용 경험은 필요하지 않다.

## 3. 학습 목표

과정을 마치면 교육생은 다음을 수행할 수 있다.

1. OCR과 Document AI의 차이를 설명하고 문서 자동화 파이프라인을 설계할 수 있다.
2. 이미지 또는 PDF 문서에서 OCR로 텍스트를 추출하고 주요 오류 유형을 확인할 수 있다.
3. 문서의 키-값, 표, 반복 항목 구조를 분석하고 필요한 추출 필드를 정의할 수 있다.
4. 생성형 AI용 프롬프트와 JSON 스키마를 작성하여 비정형 텍스트를 구조화할 수 있다.
5. Codex를 활용해 Gradio 기반 문서 자동화 앱을 구현하고 수정할 수 있다.
6. 추출 결과의 누락값과 형식을 검증하고 CSV 데이터로 내보낼 수 있다.
7. 개인정보, 보안, 오추출 위험을 고려한 사람 중심의 검토 절차를 설계할 수 있다.

## 6. 교시별 상세 운영안

### 1교시. Document AI 개요 및 문서 자동화 활용 사례

**목표**

- OCR이 문서 자동화 파이프라인의 한 단계임을 설명할 수 있다.
- 자동화할 문서와 추출할 필드를 구체적으로 정할 수 있다.

**주요 내용**

- OCR과 Document AI의 차이
- 문서 수집, 텍스트 추출, 구조화, 검증, 저장의 전체 흐름
- 영수증, 신청서, 견적서, 계약서, 점검표 자동화 사례
- 생성형 AI가 잘하는 일과 사람이 검토해야 하는 일

**실습**

1. 샘플 문서 3종의 사용 목적과 반복 처리 업무를 적는다.
2. 문서별 필수 추출 항목과 선택 항목을 구분한다.
3. 잘못 추출되었을 때 업무에 미치는 영향을 정리한다.

**산출물**

- 문서 유형, 추출 필드, 데이터 형식, 검토 필요 여부가 포함된 추출 항목 정의서

### 2교시. OCR 기반 텍스트 추출 실습

**목표**

- 이미지 또는 PDF 입력을 OCR로 처리할 수 있다.
- OCR 실패 시 mock 결과를 사용해 후속 실습을 계속할 수 있다.

**주요 내용**

- OCR의 입력과 출력
- 해상도, 기울기, 노이즈, 글꼴이 인식률에 미치는 영향
- PaddleOCR 또는 EasyOCR을 이용한 기본 추출
- OCR 설치 및 모델 다운로드 실패에 대비한 mock 모드

**실습**

1. 정상 품질 문서와 저품질 문서에서 OCR을 실행한다.
2. 원본 문서와 추출 텍스트를 비교해 오류를 표시한다.
3. OCR 실행이 어려운 환경에서는 제공된 샘플 텍스트를 불러온다.

**산출물**

- OCR 결과 텍스트와 주요 인식 오류 목록

### 3교시. 문서 구조 이해 및 추출 결과 정제

**목표**

- 문서를 키-값, 표, 반복 항목 구조로 나누어 볼 수 있다.
- OCR 텍스트를 정보 추출에 적합한 형태로 정리할 수 있다.

**주요 내용**

- 제목, 본문, 표, 서명 등 문서의 구성 요소
- 상호명-값, 항목명-값과 같은 키-값 관계
- 품목 목록처럼 반복되는 데이터 구조
- 줄바꿈, 공백, 잘못 인식된 숫자 등 대표 오류 정제

**실습**

1. OCR 결과에서 문서 영역과 항목의 관계를 표시한다.
2. 불필요한 공백과 줄바꿈을 정리한다.
3. 품목 정보를 행 단위 데이터로 재구성한다.

**산출물**

- 항목 또는 표 단위로 정리한 문서 데이터

### 4교시. 생성형 AI 기반 핵심 정보 추출

**목표**

- 문서 유형별 JSON 스키마를 설계할 수 있다.
- OCR 텍스트를 구조화하는 생성형 AI용 프롬프트를 작성할 수 있다.

**주요 내용**

- 역할, 입력, 추출 필드, 출력 형식, 제약조건으로 구성하는 프롬프트
- 영수증, 신청서, 견적서의 JSON 스키마
- 값이 없을 때의 처리 원칙과 임의 생성 방지
- JSON 문법 오류와 데이터 형식 오류의 차이

**실습**

1. 영수증 추출 스키마를 작성한다.
2. OCR 텍스트와 출력 스키마를 포함한 프롬프트를 완성한다.
3. mock 추출 결과를 스키마와 비교하고 오류를 수정한다.

**예시 결과**

```json
{
  "document_type": "receipt",
  "store_name": "샘플상점",
  "date": "2026-07-27",
  "total_amount": 15000,
  "items": [
    {
      "name": "샘플상품",
      "quantity": 1,
      "price": 15000
    }
  ]
}
```

**산출물**

- 문서 유형별 추출 프롬프트와 구조화 JSON

### 5교시. Gradio 기반 문서 자동화 데모 앱 구현

**목표**

- Gradio 컴포넌트와 Python 함수를 연결할 수 있다.
- Codex에 요구사항을 전달하고 생성된 코드를 확인·수정할 수 있다.

**주요 내용**

- 파일 입력, 이미지 미리보기, 텍스트, JSON, 버튼 컴포넌트
- 사용자 이벤트와 Python 함수 연결
- Codex 작업 요청의 목표, 맥락, 제약조건, 완료 기준
- 작은 기능 단위로 구현하고 직접 실행해 확인하는 방법

**실습**

1. Codex에 파일 업로드 화면 구현을 요청한다.
2. 업로드한 이미지 또는 PDF의 이름과 미리보기를 표시한다.
3. 샘플 OCR 텍스트와 JSON을 결과 영역에 출력한다.

**산출물**

- 로컬에서 실행 가능한 기본 Gradio 앱

### 6교시. 문서 업로드·OCR·AI 추출 기능 통합

**목표**

- 업로드한 문서를 OCR 및 JSON 추출 함수와 연결할 수 있다.
- 실패가 전체 앱 중단으로 이어지지 않도록 처리할 수 있다.

**주요 내용**

- 업로드 파일의 형식 확인과 임시 경로 처리
- OCR 실행 버튼과 결과 상태 표시
- OCR 텍스트를 추출 프롬프트에 전달하는 흐름
- 실제 추출과 mock 추출 모드 전환
- 이해하기 쉬운 오류 메시지 작성

**실습**

1. 업로드 파일을 OCR 함수에 전달한다.
2. OCR 결과를 JSON 추출 함수에 연결한다.
3. OCR 실패 시 샘플 결과로 전환되는지 확인한다.

**산출물**

- 업로드 → OCR → JSON 구조화가 연결된 Document AI 미니 앱

### 7교시. 추출 결과 검증 및 데이터 저장

**목표**

- 추출 결과의 필수값과 데이터 형식을 검증할 수 있다.
- 검증된 데이터를 표로 확인하고 CSV로 내려받을 수 있다.

**주요 내용**

- `valid`, `warnings`, `errors` 형태의 검증 결과
- 필수값 누락과 날짜·금액·이메일·전화번호 형식 검사
- JSON을 표 형태로 변환하는 방법
- CSV 인코딩과 한글 데이터 저장 시 주의사항

**실습**

1. 일부 값이 누락되거나 형식이 잘못된 테스트 데이터를 만든다.
2. 검증 함수로 오류와 경고를 화면에 표시한다.
3. 정상 결과를 표로 변환하고 CSV 다운로드를 연결한다.

**산출물**

- 검증 결과 화면과 다운로드 가능한 CSV 파일

### 8교시. 실무 적용 시나리오 설계 및 최종 정리

**목표**

- 자동화에 적합한 업무와 사람의 검토가 필요한 지점을 구분할 수 있다.
- 자신의 업무를 대상으로 도입 가능한 문서 자동화 시나리오를 작성할 수 있다.

**주요 내용**

- 흐린 이미지, 손글씨, 복잡한 표, 혼합 문서 등 실패 사례
- 개인정보 최소 수집, 안전한 저장, API 전송 전 확인 사항
- AI 결과를 확정 데이터로 사용하기 전 사람의 검토 절차
- 정확도, 처리 시간, 수정률을 활용한 개선 방법

**실습**

1. 전체 앱의 정상·오류·mock 흐름을 점검한다.
2. 개인 또는 조직의 반복 문서 업무 하나를 선정한다.
3. 입력 문서, 추출 필드, 검증 규칙, 담당자 검토, 저장 형태를 설계한다.

**산출물**

- 최종 Document AI 미니 앱
- 개인별 업무 적용 시나리오
- 운영 전 추가 개선 과제

## 7. 최종 미니 프로젝트

교육생은 다음 기능을 갖춘 문서 자동화 앱을 완성한다.

- 이미지 또는 PDF 업로드
- 업로드 문서 미리보기
- OCR 실행 및 결과 텍스트 확인
- 생성형 AI 추출용 프롬프트 생성
- 문서 유형에 맞는 샘플 또는 실제 JSON 결과 표시
- JSON 결과의 표 변환
- 필수값과 날짜·금액 형식 검증
- 검증 결과의 오류·경고 표시
- CSV 다운로드
- OCR 또는 API 사용이 어려울 때의 mock 모드

### 완료 기준

- 앱이 로컬 환경에서 정상 실행된다.
- 정상 문서와 오류 문서의 처리 결과를 구분해 보여 준다.
- OCR 설치 실패 시에도 샘플 결과로 3~8교시 실습을 계속할 수 있다.
- 실제 API 키나 개인정보가 코드와 샘플 파일에 포함되지 않는다.
- 교육생이 자신의 업무에 적용할 문서 유형과 검증 절차를 설명할 수 있다.

## 8. 실습 운영 원칙

### Codex 활용

- 요구사항을 한 번에 크게 요청하지 않고 화면, OCR, 추출, 검증, 저장 기능으로 나누어 작업한다.
- Codex가 만든 코드는 교육생이 직접 실행하고 입력과 출력의 관계를 확인한다.
- 오류가 발생하면 오류 메시지, 실행 환경, 기대 결과를 함께 전달해 수정한다.
- 생성된 코드의 API 키, 개인정보, 파일 경로 하드코딩 여부를 확인한다.

### 대체 실습 경로

| 문제 상황 | 대체 방법 |
| --- | --- |
| OCR 라이브러리 설치 실패 | `sample_outputs/ocr_result.txt` 사용 |
| OCR 모델 다운로드 실패 | mock OCR 모드로 전환 |
| PDF 변환 실패 | 동일 내용의 샘플 이미지 사용 |
| 생성형 AI API 키 없음 | 제공된 프롬프트와 mock JSON 사용 |
| Gradio 실행이 어려움 | 함수 단위 실습을 진행하거나 Streamlit 대체 자료 사용 |
| Codex 사용 불가 | 제공된 시작 코드와 프롬프트 템플릿으로 실습 |

### 과정 범위

이번 8시간 입문 과정에는 대규모 배포, 데이터베이스, 사용자 인증, 모델 학습, React/Next.js 프런트엔드 구현을 포함하지 않는다. 이러한 주제는 미니 앱 완성 후의 확장 방향으로만 소개한다.
