## 매 교시 운영 리듬

아래 리듬은 2~8교시에 적용한다. 1교시는 OCR·멀티모달·VLM·Document AI·IDP의 경계와 전체 0~12단계 절차를 정확히 설명하기 위해 별도 60분 운영표를 사용한다.

| 구간 | 시간 | 운영 |
| --- | ---: | --- |
| 문제·핵심 메시지 | 6분 | 오늘 만드는 산출물과 핵심 개념 최대 3개 |
| 첫 실행 | 9분 | 완성 예와 복구 기준 확인 |
| 개별 실습 | 32분 | 직접 작성 10~15줄, 나머지는 실행·비교·수정 |
| 복구·검증 | 10분 | 3분 복구본 전환, 원본 대조, 기대 결과 확인 |
| 연결 | 3분 | 산출물을 저장하고 다음 교시 입력 확인 |

## 실패 시 우회 순서

1. 오류 메시지를 학습자와 함께 읽는다.
2. 같은 셀을 한 번만 다시 실행한다.
3. 3분 안에 해결되지 않으면 해당 교시의 완성 복구본으로 이동한다.
4. Streamlit AppTest 문제면 처리 함수를 셀에서 직접 호출한다.
5. 해당 교시의 산출물이 생성되면 다음 단계로 진행한다.

mock 사용 사실은 반드시 화면과 설명에서 공개한다.

## 시간이 부족할 때

생략할 수 있는 내용:

- PaddleOCR-VL 실제 다운로드와 실행
- 상용 VLM 비교 시연
- Office 원본·PDF 텍스트층·표 캡처 비교의 세부 코드
- PDF 선택 실습
- 선택 확장 질문

생략하면 안 되는 내용:

- mock과 실제 결과의 구분
- 식별정보를 가린 실제 영수증 OCR 시도와 3분 복구 기준
- 원문에 없는 값은 `null`
- 필수값·품목 합계 검증
- 개인정보와 사람의 최종 검토

## 초보자 질문 대응

**“신뢰도가 99%면 맞는 것 아닌가요?”**

신뢰도는 OCR 엔진 내부 신호다. 금액처럼 영향이 큰 값은 원문과 검증 규칙으로 다시 확인한다.

**“준비된 결과면 가짜 실습 아닌가요?”**

2교시에서 실제 영수증 OCR을 먼저 시도한다. 준비 결과는 설치·다운로드가 3분 안에 끝나지 않을 때 원본 대조와 구조화 학습을 계속하기 위한 복구본이며, 실제 모델 실행 결과처럼 표시하지 않는다.

**“PaddleOCR-VL이 표를 읽으면 값도 정확한가요?”**

아니다. 모델의 Markdown·블록 결과를 업무 JSON으로 바꾸고, 값이 원문과 같은지 별도로 검토한다.

**“왜 실제 회사 문서를 쓰지 않나요?”**

Colab과 공개 웹앱 주소, 외부 API의 데이터 처리 조건을 확인하지 않은 교육 환경이기 때문이다.
